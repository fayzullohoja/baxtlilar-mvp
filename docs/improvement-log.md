# Baxtlilar — журнал непрерывных улучшений

Этот файл ведёт автоматический цикл улучшений (`/loop`, каждые 10 минут).
Цель цикла: искать баги — **системные и бизнесовые** — исправлять их, улучшать
код там, где можно сделать лучше, и документировать каждое изменение.

**Правила цикла:**
- Один логический шаг за итерацию: найти → исправить → протестировать
  (`pnpm test:run` / `pnpm typecheck`) → задокументировать здесь → при готовности
  задеплоить (`railway up` или push в `main` = автодеплой Railway).
- Ничего полусырого в `main`. Прод-БД мутации откатываются после тестов.
- Каждая запись: **дата · что нашли · почему это баг · как починили · как проверили**.

## 2026-06-17 — Старт цикла

### Контекст на момент старта
- Прод: `https://baxtlilar-mvp-production.up.railway.app` (Railway + native Postgres + Volume `/data`).
- Стек: Next.js 16 (App Router), React 19, TS strict, native-`pg` query-builder
  (`src/lib/db/`), next-intl 4 (RU/UZ), Vitest, Zod.
- Известный класс багов: **PostgREST embed-синтаксис** (`table(cols)`, `!inner`,
  dotted-фильтры) — native-адаптер его НЕ поддерживает и кидает ошибку, а call-site,
  игнорирующий `.error`, тихо рендерит пустую страницу.

### Уже закрыто (предыдущая сессия, фиксируется для истории)
**Баг:** очередь модерации фото (`/admin/photos`) показывала «0 фото» при наличии
записей `under_review` — нельзя было одобрить фото. Корень: embed `users(...)` в
`.select()` кидал ошибку в `ident()`, она глоталась в `run()`, страница получала
`null` → пусто. Тот же дефект затрагивал `/admin/audit` и `/admin/users`.

**Починка:**
- `src/lib/db/query-builder.ts` — `ident()` теперь кидает понятную ошибку на embed
  и dotted-пути; `compile()` вынесен из try/catch (ошибки компиляции — громкие 500,
  ошибки раннера/БД — мягкие `{data:null,error}`).
- `src/lib/db/unwrap.ts` (новый) — `unwrapRows()` поднимает рантайм-ошибки БД на
  страницах админки вместо «тихо-пусто».
- `/admin/photos`, `/admin/audit`, `/admin/users` переписаны: вместо embed —
  отдельный запрос `.in(...)` + сшивка в JS; все чтения через `unwrapRows`.
- Тесты на embed/dotted throw + `unwrapRows` (89 тестов зелёные).

**Проверено:** живьём на проде через Playwright — очередь фото отображается, одобрение
работает; тест-мутация в прод-БД откачена.

## 2026-06-17 · Итерация 1 — silent-empty/false-404 на всех страницах админки

**Что нашли (системный + бизнесовый баг).** Аудит показал, что embed-синтаксис в
коде приложения вычищен полностью (остались только намеренные regress-тесты). Но
сам *класс* «тихо-пустых» страниц шире embed: **все оставшиеся страницы админки
читали `const { data } = await sb…` и игнорировали `error`**, подставляя `?? []`,
`?? 0`, `?? null`. Значит при ЛЮБОМ сбое БД (обрыв пула, таймаут) страница молча
показывала «пусто», а не ошибку:
- `/admin` (дашборд) — «0 заявок на проверке / 0 жалоб» → модератор не видит бэклог;
- `/admin/verifications` — «Очередь пуста» → заявки на верификацию зависают незаметно;
- `/admin/verifications/[id]` — `maybeSingle()`→null→`notFound()` → **ложный 404** на
  реально существующего пользователя;
- `/admin/reports` — «Открытых жалоб нет»;
- `/admin/analytics` — «Нет данных».

Это бизнес-риск: модерация принимает «тихо-пусто» за «работы нет».

**Как починили.**
- `src/lib/db/unwrap.ts` — к `unwrapRows` добавлены два хелпера:
  - `unwrapCount({count,error})` → бросает на error, иначе `count ?? 0` (для
    `select('*',{count:'exact',head:true})` на дашборде);
  - `unwrapOne({data,error})` → бросает на error, иначе `data ?? null` (для `rpc()` и
    `maybeSingle()`; отделяет «реально нет строки» от «БД упала»).
- Применены ко всем 5 страницам: `/admin` (page.tsx), `/admin/analytics`,
  `/admin/reports`, `/admin/verifications`, `/admin/verifications/[id]`.
- Поведение happy-path не меняется; меняется только сбойный путь: видимая 500
  вместо ложного «пусто»/404.

**Как проверили.**
- `pnpm typecheck` — чисто.
- `pnpm test:run` — 98 тестов зелёные (добавлено 6: по 3 на `unwrapCount`/`unwrapOne`).
- `pnpm lint` — изменённые файлы чисты (остаются прежние `any`-ошибки в
  `query-builder.ts` — см. бэклог ниже).

**Бэклог (найдено, отложено — не в скоупе этой итерации):**
- `src/lib/db/query-builder.ts` и `query-builder.test.ts` — 7 ошибок eslint
  `no-explicit-any`. Эти `any` несущие (на них опирается вывод типов строк во всех
  call-site'ах админки); правильный фикс — точечный `eslint-disable` с пояснением,
  а не замена на `unknown`. Не блокирует сборку (`next build` не гейтит на eslint).
