# Anketa V5 — финализированная контент-спека оунеров, замаппленная на код (2026-07-07)

Оунеры прислали финальную контент-спеку анкеты (RU/UZ, с аккуратными смягчёнными формулировками). Ниже — точный маппинг на текущий код V4 (`src/lib/profile/options.ts`, `schemas.ts`, `state-machine/*`). Заземлено на реальные enum-наборы.

**Инфраструктура, которая уже есть и переиспользуется:** gender-conditional рендер (`getGenderedOptionLabel`/`getGenderedQuestion`, `gender-wording.ts`), `extended` jsonb + `splitHotCold`, каскад `CITIZENSHIP`→`COUNTRY_OF_RESIDENCE`/`PARTNER_PREFERRED_COUNTRIES`, `UZ_REGIONS`/districts, матчинг землячества (`birth_region`).

**Легенда эффорта:** S=правка enum/лейблов, M=новое поле+форма+валидация, L=новый экран/структурная переработка.

## Маппинг по 13 разделам

### 1. Страны (CITIZENSHIP)
- **Сейчас (8):** UZ, RU, KZ, KG, TJ, TM, TR, OTHER. Каскадит в `COUNTRY_OF_RESIDENCE` и `PARTNER_PREFERRED_COUNTRIES`.
- **Цель (16):** +США, Ю.Корея, Япония, Сауд. Аравия, ОАЭ, Катар, Индонезия, Малайзия. (Оунер НЕ включил Туркменистан — уточнить, убирать ли.)
- **Дельта:** расширить `CITIZENSHIP` → каскад в 3 места автоматом. Эффорт **S**, миграции нет (text). ⚠️ `region` детально только для UZ; для новых стран регион — freeform (уже так).

### 2. Дети — 2 уровня
- **Сейчас:** `has_children` (no/yes/na) ✅, `children_count` ✅, `child_age` (один, младший) ✅, `children_plan`. Нет по-детной структуры и «с кем живёт».
- **Цель:** осн. вопрос ✅; если «да» → количество 1/2/3/4/5+; **по каждому ребёнку**: пол (сын/дочь/не указывать), возраст (точный или диапазон), с кем живёт (со мной / с другим родителем / с родственниками / не указывать).
- **Дельта:** массив `children[]` в `extended` `{gender, age_or_range, lives_with}` + новые enum `CHILD_GENDER`, `CHILD_LIVES_WITH`; прогрессивное раскрытие при `has_children='yes'`. **Имя ребёнка НЕ собираем** (оунер убрал — совпало с рекомендацией). Эффорт **M**, миграции колонок нет (jsonb). ⚠️ возраст/пол ребёнка — ПД несовершеннолетнего → hidden public + правовой контур.

### 3. Семейный статус — гендерное разделение
- **Сейчас:** `MARITAL_STATUS` = never/divorced/widowed/other (4, БЕЗ гендер-ветвления).
- **Цель:**
  - **М:** не был в браке / разведён / вдовец / в браке, но живёт раздельно
  - **Ж:** не была в браке / *есть опыт прошлых отношений* / разведена / вдова / в браке, но живёт раздельно
- **Дельта:** сделать `MARITAL_STATUS` gender-conditional (инфра есть). Добавить `married_separated` (оба), `prior_experience` (только Ж). Убрать `other`. Одна колонка, union значений. Эффорт **M**, миграция (расширить CHECK/enum + бэкфилл `other`). ⚠️ Оунер намеренно смягчил Ж-опцию (без «девственница»/«обманутая») — оставить точную формулировку. `married_separated` — **РЕШЕНО оунером: да**.

### 4. Планы на детей — 2 вопроса
- **Сейчас:** `FUTURE_CHILDREN_PLAN` (5) — один вопрос.
- **Цель:** Q1 (хочу в будущем): хочу / пока не хочу / нет, не в планах / обсуждается отдельно. Q2 (взгляд на количество): 1–2 / 3–4 / многодетная / не уверен / обсуждается.
- **Дельта:** Q1 — реворд под 4 опции; Q2 — **новый** enum `CHILDREN_COUNT_VIEW` (+поле). Эффорт **S–M**. Формулировки смягчены (без «очень не хочу многодетство»).

### 5. Возможность иметь детей (чувствительное, смягчено)
- **Сейчас:** нет.
- **Цель:** «Ваша ситуация по вопросу детей»: есть возможность / обсуждается отдельно / есть личная ситуация / не хочу отвечать.
- **Дельта:** новый enum `CHILDREN_CAPABILITY`. Эффорт **S**, но ⚠️ **ЗАБЛОКИРОВАНО правовым контуром**: даже смягчённое «личная ситуация» подразумевает здоровье → спец-категория ПД. Optional + hidden public + согласие. **Вопрос юристу:** снимает ли мягкая формулировка классификацию как данные о здоровье.

### 6. Модель семьи (мягко, 3 опции)
- **Сейчас:** `FAMILY_ROLE_MODEL` = traditional / equal_partnership / woman_leads / **situational** (4).
- **Цель (3):** семья с лидерством мужчины / семья с лидерством женщины / равное партнёрство.
- **Дельта:** **убрать `situational`** (закрывает вопрос-развилку), смягчить лейбл traditional, оставить `woman_leads` + `equal_partnership` (дубля нет — оунер подтверждает 3). Эффорт **S**, миграция (drop value + бэкфилл существующих `situational`).

### 7. Финансовое/рабочее состояние (упрощение)
- **Сейчас:** `EMPLOYMENT` (8) + `EMPLOYMENT_FORMAT` (5) + finance-экран (`INCOME_SOURCE_STABILITY` и т.д.).
- **Цель (5):** работаю / учусь / предприниматель / пока не работаю / не хочу отвечать.
- **Дельта:** оунер хочет **простой** статус. ⚠️ Пересечение с существующими `EMPLOYMENT`/`EMPLOYMENT_FORMAT`. **Развилка:** упростить `EMPLOYMENT` до 5 опций ИЛИ добавить новое coarse-поле рядом с finance-экраном. Эффорт **S–M**. Требует решения.

### 8. Образование (уровень)
- **Сейчас:** `EDUCATION` = secondary/vocational/higher/master/studying/courses/na (7).
- **Цель (6):** среднее / среднее спец. / высшее-бакалавр / магистр / **PhD/учёная степень** / не хочу отвечать.
- **Дельта:** **добавить PhD** (сейчас нет!), реворд higher→«Высшее/Бакалавр», убрать studying/courses (studying покрыт статусом работы). Эффорт **S**, миграция (add value). *(«В какой сфере» из прошлого батча = `activity_field`, уже есть.)*

### 9. Жильё
- **Сейчас:** нет.
- **Цель (5):** своё жильё / аренда / с родителями-родственниками / пока нет своего / не хочу отвечать.
- **Дельта:** новый enum `HOUSING_STATUS` + колонка. Эффорт **S**, миграция. **РЕШЕНО оунером: включаем.** «Не хочу отвечать» снижает стигму «нет жилья».

### 10. Родители и семья (БОЛЬШОЙ новый блок)
- **Сейчас:** нет (отложенная задача #82 «Экран Родители»).
- **Цель:** блок после «О себе», до «Кого ищу». Отец И мать (каждый): жив/умер/не указывать, возраст-или-диапазон, профессия, место рождения (страна/регион/город), текущее проживание, семейный статус. + семейный статус родителей (вместе/разведены/отец умер/мать умерла/оба умерли/другое/не указывать) + отношения с семьёй (близкие/обычные/мало общаемся/живу отдельно/не указывать) + участие семьи в браке (хочу чтобы семья знала / решаю сам / обсуждается).
- **Дельта:** **новый экран** + jsonb `parents{father{}, mother{}, marital, relationship, marriage_involvement}` + ~4 enum. Эффорт **L** — самый крупный пункт. ⚠️ **ПД третьих лиц** (родители) → правовой контур. Имена родителей НЕ собирать. Контент теперь определён (разблокирует #82 по содержанию, но не по правовому гейту). Место рождения родителей может стать сигналом землячества в матчинге.

### 11. План проживания после брака
- **Сейчас:** `POST_MARRIAGE_LIVING` (4).
- **Цель (6):** с родителями мужа / с родителями жены / отдельно / временно с родителями, потом отдельно / по договорённости / пока не ясно.

### 12. Готовность к браку (НОВОЕ)
- **Сейчас:** нет.

### 13. Готовность к переезду (НОВОЕ/расширение geo)
- **Сейчас:** `GEO_PREFERENCE` = my_city/country (2) — частично.
- **Цель (4):** готов переехать в др. город/страну / только мой город / по договорённости / пока не ясно.
- **Дельта:** новый enum `RELOCATION_READINESS` (семантика ≠ geo_preference: готовность переезжать vs где искать). Эффорт **S**.
