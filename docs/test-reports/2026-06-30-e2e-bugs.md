### ✅ Bug #3 — recommend.ts + get_recommendations RPC селектят dropped 'values' — FIXED

**File:** `src/lib/matching/recommend.ts:22` + `supabase/migrations/20260626000000_v2_recommendations_viewer_gate.sql:23,36`

**Severity:** CRITICAL — silent feature failure для ВСЕХ verified юзеров.

**Что не так:** `recommend.ts:22` делает `select("city, values, birth_date")` где колонка `values` ДРОПНУТА в Sprint 3 cleanup (миграция `20260629000000_drop_deprecated_v2_fields.sql`). Supabase-js при ошибке колонки молча возвращает `data=null`, guard на :26 ставит `return []`. RPC `get_recommendations` тоже селектит `vp.values as vals` и `cp.values as vals` — на проде RPC падает. **Reproduced:** теоретически (verifier подтвердил через чтение кода) — у нас сейчас 1 active юзер, но feed empty проверяемо.

**Fix:**
1. Создана миграция `20260630000000_recommendations_v3_top_life_values.sql` — пересоздаёт RPC с `top_life_values` вместо `values`. Применена на проде.
2. `recommend.ts` — select `top_life_values` вместо `values`; правильное приведение в `ScoreInput`.

### ✅ Bug #4 — Ready state dead-end (interrupted tutorial) — FIXED

**File:** `src/app/api/onboarding/welcome/route.ts`

**Severity:** CRITICAL — юзер навсегда застревал.

**Что не так:** tutorial route делает ready→active отдельной второй транзакцией (`tutorial/route.ts:86-96`). Если она падает (DB/network/crash), юзер остаётся `onboarding_step='ready'` и `lifecycle_state='onboarding'`. Router отправит на `/v2/welcome`, но welcome route отвергает `ready` как `wrong_step`. Полный тупик — только ручной DB edit.

**Fix:** welcome route теперь распознаёт `ready` и завершает финальный переход `ready → active + lifecycle_state=active`. ALLOWED_TRANSITIONS.ready=["active"] уже разрешает это.

### ✅ Bugs #10-#12 — Admin audit, SLA, token GC — FIXED

#### Bug #10: Admin login success не пишется в audit_log

**File:** `src/app/api/admin/login/route.ts`
**Severity:** major (compliance/forensics)

**Что не так:** `recordLoginAttempt(ip, true)` пишет в `admin_login_attempts` (rate-limit таблица без admin_id FK). `admin_audit_log` — отдельная forensic-таблица. После успешного login админа в audit_log пусто.

**Fix:** добавлен `adminAudit({action:"login", entity:"admin", ip})` после `recordLoginAttempt`. Сбой аудита не блокирует login (try/catch).

#### Bug #11: Нет SLA / auto-decline для stale verification cases

**File:** `supabase/migrations/20260630010000_verification_case_sla.sql` + `src/app/api/cron/housekeeping/route.ts`
**Severity:** minor

**Что не так:** если модератор взял case (state=`assigned`) и абандонил, кейс не виден в `/admin/queue/unassigned` (state != 'new') И не виден в `/admin/queue/mine` другим модераторам (`assignee_id != null`). Юзер навсегда в pending_review.

**Fix:**
- Новая RPC `admin_sla_reclaim_stale_cases(p_max_idle_hours=168)` — снимает claim после 7 дней idle, возвращает state→'new', assignee_id→null.
- Новый cron endpoint `/api/cron/housekeeping` (X-Cron-Secret + Railway scheduled job).

#### Bug #12: `gc_start_token_uses()` RPC не вызывается

**File:** `src/app/api/cron/housekeeping/route.ts`
**Severity:** minor (table растёт unbounded, но строки tiny)

**Что не так:** RPC существует в миграции `20260620920000_split_window_and_jti_fixes.sql:226`, чистит истёкшие токены (TTL=600s). Никто не вызывает — `start_token_uses` растёт.

**Fix:** housekeeping cron вызывает `gc_start_token_uses()` 1/час.

### ✅ Bug #16 — document_sha_blacklist не enforce'ится — FIXED

**Files:** `src/app/api/onboarding/{document,selfie,fix}/route.ts` + new `src/lib/uploads/blacklist.ts`

**Severity:** CRITICAL — security gap. Banned юзер (после blocking-reject) мог re-uploadить те же документы под новым telegram_id, обходя блок.

**Что не так:** `document_sha_blacklist` (append-only tombstone) заполнялась `admin_blocking_reject` и `erase_user` RPC, но никогда не SELECT'илась на upload paths. `grep -r 'FROM.*document_sha_blacklist' src/` → 0 хитов.

**Fix:** новый helper `isDocumentBlacklisted(sha, kind)` + проверка в document/selfie/fix route ПОСЛЕ `uploadDocumentImage` ДО записи в DB. При совпадении SHA → 400 `document_blacklisted`.

### ✅ Bug #17 — admin_blocking_reject RPC сломан constraint mismatch — FIXED

**File:** `supabase/migrations/20260630020000_admin_blocking_reject_constraint_fix.sql`

**Severity:** CRITICAL — blocking-reject не работал на проде.

**Что не так:** RPC определена в миграции `20260620800000_final_adversarial_fixes.sql` с `on conflict (sha256, kind) do nothing`. Миграция `20260620920000_split_window_and_jti_fixes.sql` ДРОПНУЛА этот constraint и заменила на `(sha256, kind, source_user_id, reason)`. RPC не была пересоздана → на проде падала с PostgreSQL error 42P10 → транзакция rollback → юзер оставался в `pending_review` несмотря на "успешный" blocking-reject.

**Fix:** новая миграция пересоздаёт RPC с правильным conflict target. Применена на проде.
